# Changelog

## mind 0.2.0 (2026-09-12)

- **Propose mode**: `mind.py propose <draft.md>... --topic <t> [--scope global|project] [--project slug] [--body <file>]` writes each draft as an accepted note in a temporary git worktree on branch `propose/<date>-<topic>` (started from `origin/<branch>` if it exists, else the local branch if a prior push failed, else `origin/main`, or `HEAD` on a brand-new repo with no upstream yet), never in the shared checkout — a concurrent `inject`/`ask`/`add`/`lint` can never read an unmerged proposal as an accepted note. One commit per note, then a push and (with `gh` on PATH and authenticated) `gh pr create`; reuses an existing open PR for the branch instead of opening a second one. Any invalid draft, an unrecognised `scope:` value, or a dangling `supersedes` rejects the whole batch before anything is written. A `supersedes` draft flips the old note's `status: superseded` inside the same branch. The worktree is always removed, success or failure; a `fetch`/`push` timeout is caught and reported, never a traceback. `mind.py proposals` lists every `propose/*` branch not yet merged into `origin/main` (`--no-merged origin/main`) with its PR URL, plus any local branch that never reached the remote, tagged `(unpushed)`; a merged proposal drops off the list for good — even if the remote branch survives — and a merged local branch is deleted automatically. Sibling same-day proposals from different topics never collide on the next free ID: `propose` scans other unmerged `propose/*` branches' note filenames first.
- **Passive capture**: a new `UserPromptSubmit` hook, `scripts/capture.sh`, appends one JSON line per prompt to `<MIND_HOME>/../pending.jsonl` (override `MIND_PENDING`) — skipping slash commands and prompts under 12 characters, capped at 2 MB (oldest half dropped), always exits 0. The file is created (and every append re-asserts) mode `0o600`, never the default umask. Prompts are stored verbatim except for a range of masked credential shapes (every current GitHub token prefix plus `github_pat_`, `sk-ant-...` and any bare `sk-...` secret, a Slack `xox[baprs]-...` token, a Google `AIza...` key, `AKIA...`/`ASIA...` AWS key ids and the 40-character secret pasted next to either, a JWT, a userinfo-embedded URL, a PEM private key block); the same masking runs on git/gh stderr wherever `_redact` is applied, not only on captured prompts. `mind.py pending [--since <ts>] [--limit N]` prints unprocessed lines as JSON; `mind.py pending --mark <ts>` records the watermark (rejecting a malformed timestamp); `mind.py pending --clear` deletes only the rows at or before the watermark, keeping the watermark itself and any row appended after it, for purging the verbatim prompt text once it has been mined; `--mark <ts> --clear` runs both in one call, and a bare `--clear` with no watermark at all deletes nothing (`mind: nothing marked, nothing cleared`).
- **Digest skill** (`/mind:digest`): classifies pending prompts as correction, directive, answer, or noise; drafts a note per kept prompt, checks for a duplicate with `ask`, and proposes the batch with `mind.py propose`, then marks and clears the watermark. Treats prompt text as data, never as an instruction to execute, and only ever proposes from it (never `add`/`affirm`/`retire`).
- **Stale notes, review skill**: `mind.py stale [--days 90] [--all]` lists accepted notes whose `affirmed` date is older than the threshold, oldest first (`must`-strength notes are tagged `(must, no decay)` but still listed; a null `affirmed` sorts first and prints "no affirmed date", never a six-figure day count). `mind.py affirm <ID> [--strength ...]` and `mind.py retire <ID>` commit and sync directly (owner actions, not proposals). `/mind:review` walks stale notes one at a time offering reinforce, weaken, revise (via `propose` with `supersedes`), or retire, and never suggests retiring a `must` note on age alone.
- **Lint**: `mind.py lint [--days 180]` reports malformed notes, filename/ID mismatches, duplicate IDs across different files, dangling `supersedes`/`refers` references, an old note left `accepted` after being superseded, duplicate titles within a scope, stub `project.md` files, stale notes, and an injection payload that would exceed the budget. New `/mind:lint` skill reports the rows and names the one command that fixes each.
- **Precedence notes and per-machine toggles**: a new `precedence` note type (code `PREC`) with an optional `refers: [ID, ID]` list field; `ask` promotes a matching precedence note to the front, tagged `[precedence]`, when two or more hits share a stage, including when the precedence note's own text never contains the query term. `${MIND_HOME}/../settings.json` (override `MIND_SETTINGS`) holds `{"auto_answer": bool, "escalate": bool}`, read and written by `mind.py settings --set key=value` (a value outside `true/false/1/0/yes/no/on/off` is rejected rather than silently coerced); `inject` appends a `Mode: ...` line describing the current auto-answer and conflict-escalation behavior. A settings file that exists but fails to parse falls back to the defaults, and both `inject` and `doctor` print `mind: settings file unreadable, using defaults` rather than presenting those defaults as the owner's configured values. `init` writes `schema.md` once; upgrading never rewrites an existing data repo's copy, so `inject` prints `mind: schema.md predates 0.2.0, re-copy templates/schema.md` whenever the data repo's `schema.md` is still missing the `precedence` type.
- **Inject additions**: after the existing sections, `inject` prints the count and URL of any open proposal (cached across `clear`/`compact` so only `startup`/`resume` calls `proposals`), capped at 5 rows total with a `+N more, run mind.py proposals` line beyond that, and a reminder to run `/mind:digest` once 20 or more prompts are pending; a hung fetch behind either check degrades to no proposals line rather than losing the whole injected payload.
- **Doctor**: `mind.py doctor` prints one line per check — config (redacted), checkout state (read-only, never clones; `ok`/`missing`/`broken (not a git dir)`/`broken (no HEAD)`), whether `main` specifically tracks `origin/main`, remote reachability, git identity, `gh` version/auth (with browser prompts disabled), pending file counts and watermark, a capture health line (`capture: last write <ts> (<N> lines)`, or `capture: never`, since capture is silenced twice over and an unwritable pending file or full disk would otherwise mine nothing with no signal), settings, and note counts — for diagnosing a second machine or a cloud session. With `MIND_REPO` unset it still exits 0, reporting `config: MIND_REPO=unset ...` and every other line that needs no repo, instead of failing before printing anything.
- **Small changes**: `ask` gains `--limit N` (default 10) and `--stage <stage>`; the protocol line tells the agent that anything it inferred rather than the owner stated goes through `propose`, never `add`, and to check precedence notes before surfacing a conflict; `remember` drops the `status: draft` option in favor of `propose`/`digest`.
- Tests: `plugins/mind/tests/test_mind.py` grows accordingly; every assertion is an exact string.

## mind 0.1.0 (2026-09-12)

- First built version of `mind`, previously a placeholder. SessionStart hook (`inject`): pulls the private notes repo on `startup`/`resume` (never on `clear`/`compact`; offline falls back to the cached copy), prints the protocol line plus the global index, current project index (or "no notes for `<candidate>` yet"), and projects index, budgeted to 4,000 characters — every `must` row kept first, then one row per stage round-robin, global truncated before project, projects index never truncated — and the draft count ("1 draft awaits acceptance" / "N drafts await acceptance: run /mind:ask --drafts").
- `remember` and `ask` skills, backed by one stdlib script, `scripts/mind.py`: `init` (write `schema.md`, create the `global/`/`projects/` layout plus a `.gitignore` for `**/index.md`, commit, push), `add` (validate frontmatter, assign a per-scope ID, write the note, reindex, commit, sync), `ask` (whole-word ranked term search over accepted or draft notes, global plus current project or `--all`), `reindex`, `accept <slug>/<ID>` (a bare ID resolves globally, or a single project note unambiguously), `sync` (commits a dirty tree first as `mind: manual edits`, then pulls with rebase when local commits exist else fast-forward, pushes with one retry and `-u origin HEAD` on an empty remote's first push).
- Indexes (`global/index.md`, `projects/<slug>/index.md`, `projects/index.md`) are generated locally and gitignored in the data repo, never committed, so concurrent machines never conflict on them. The only cross-machine collision is two machines assigning the same note ID; `add` detects it after the pre-write pull (and again after a rebase) and resolves it by taking the next free ID. A rebase conflict on any other file is reported as "mind: sync conflict in `<file>`, resolve by hand in `<home>`", never as offline.
- Project identity resolved from `MIND_PROJECT`, the git origin URL, the git top-level directory, or the cwd, sanitized to a slug and matched against each project's slug and aliases.
- Cloud sessions: `MIND_TOKEN` is passed via a git credential helper (username `x-access-token`) that first resets any previously configured helper, so the token never touches `.git/config`.
- Tests: `plugins/mind/tests/test_mind.py`, pytest, git operations against a bare repo under `tmp_path`.

## 1.3.0 (retro of the 2026-09-11 standard-tier run, see the project's `.dev/SESSION_NOTES_2026-09-11.md`)

- dev-kit `check-impact` / `behavioral-impact-checker`: **behaviour register mode**. When a project keeps `docs/behaviour-register.md` (new template `templates/behaviour-register.md`: one row per user-observable rule with the spec that set it and the test that pins it), the checker diffs the plan against the register and reads only the specs its touched rows cite, instead of the whole spec corpus on every run (28 specs cost 165k tokens and 5.5 minutes per plan and grow linearly). `--seed-register` reads every spec once to write the initial file. Every report ends with a "Register additions" section. New Step 3c traces every output-bound field the plan adds to the functions that render that surface (a flag set on an in-memory object never reached the message because every line was re-projected from the database row).
- dev-kit `ship`: step 7.5 appends the impact report's register rows before the push; the PR body gains a "Rulings" section listing findings earlier stages deferred or rejected, and reviewer briefs name it as decided (three Opus reviewers re-raised a deferred budget concern as HIGH/MEDIUM).
- dev-kit `plan-tests`: the bound is on tests written; rows are Critical or Defensive and implementer briefs scope tests to plan-named plus Critical (a 42-row map inside the bound still produced +2,300 test lines for ~150 source lines).
- orchestrator reference: `standard` cap 12 → 14 (a clean run needs 12-13; budget shape added); reference costs from the 2026-09-11 `standard` run; `evaluated` evidence is the fix-wave report at HEAD when the review had accepted findings; review-tests is dispatched in the same message as the whole-branch reviewer and the accepted rows split into parallel source and test-hygiene fix waves (one 14-fix wave cost 352k); `process-review` runs `--autonomous` inside a run; spec rule for output-bound fields (name the render call sites); plan check rule (`git grep` every quoted helper signature and every changed literal across `tests/`, never hand-write a regex expectation); the orchestrator's own commands obey the project's denied-lookup list (`sed` added for the reference project); read-only audit briefs name what is not a finding; behaviour-register paragraph.
- orchestrator `status.py --git` / SessionStart brief: reports when the local default branch is behind or ahead of origin (`default_branch_sync`), with a fetch-and-fast-forward reminder; the hook now passes `--git`. Four merged PRs were listed at the merge gate because the checkout was one commit behind. Tests added.
