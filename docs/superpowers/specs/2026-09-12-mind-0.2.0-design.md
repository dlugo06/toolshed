# mind 0.2.0: proposals as pull requests, capture, digest, review, lint

Date: 2026-09-12
Status: approved design
Plugin: `plugins/mind` in the `toolshed` marketplace, extending 0.1.0
(`docs/superpowers/specs/2026-09-11-mind-0.1.0-design.md`, which remains the
base contract; this document only adds or changes).

## 1. Purpose

0.1.0 made the mind readable and writable. 0.2.0 makes it grow without the
owner typing notes, and reviewable by the owner as diffs:

- **Proposals arrive as pull requests** on the data repo. Anything an agent
  inferred (a digest, a seeding batch, a provisional ruling) is a PR the
  owner reads as a diff. Only a fact the owner stated in the session is
  pushed to `main` through `remember`. Owner ruling, 2026-09-12.
- **Passive capture** of every prompt into a local pending file, so a
  digest can mine corrections and directives later.
- **Digest**, **review**, and **lint** skills that keep the mind current.
- **Precedence** notes and per-machine **toggles** from the 2026-09-06
  research.
- **Doctor**, so a second machine or a cloud session can report why the mind
  is not working.

The second half of the 0.2 effort, making the orchestrator and dev-kit plugins
consult the mind and route their rulings through proposals, is a separate
spec: `docs/superpowers/specs/2026-09-12-mind-integration-design.md`.

## 2. Propose mode

New subcommand:

```
mind.py propose <draft.md>... --topic <t> [--scope global|project] [--project slug] [--body <file>]
```

Behaviour:

1. Validate every draft first; any invalid draft rejects the whole batch with
   the file name and the errors, nothing written.
2. Fetch. Create a temporary git worktree beside the checkout on the branch
   `propose/<YYYY-MM-DD>-<topic>` (topic slugified with the project slug
   rules), started from `origin/<branch>` when it already exists on the
   remote, else from `origin/main`. The shared checkout never leaves `main`,
   so a concurrent inject, ask, or add can never read an unmerged proposal as
   accepted notes. The worktree is removed when the command ends, success or
   failure.
3. Write each draft as a note with `status: accepted` (merging the PR is the
   acceptance), the same ID assignment, scope, and defaults as `add`. Each
   draft's own `--scope`/`--project` may be overridden per file by a
   `scope:` line in its frontmatter (`global` or `project:<slug>`); the
   command flags are the default for drafts that carry none.
4. One commit per note, `mind: propose <ID> <title>`, then push the branch
   with `-u`.
5. Open the PR with `gh pr create --base main --head <branch>` when `gh` is
   on PATH and authenticated; title `mind: <topic> (<N> notes)`; body from
   `--body <file>` when given, else generated: one line per note
   `- <ID> | <title> | <scope> | <strength>` followed by the note's first
   paragraph, then a "Source" line naming the date and project. When a PR
   for the branch already exists, push updates it and the body is left alone.
6. Remove the worktree; print `mind: proposed <N> notes on <branch>, PR <url>` or, without
   `gh`, `mind: proposed <N> notes on <branch>, open the PR by hand`.

The `draft` status and `accept` stay for compatibility, but no skill writes
`status: draft` any more; the remember skill's text drops the option.

`mind.py proposals` lists open `propose/*` branches on the remote with their
PR URL when `gh` is available; used by inject (section 8) and by the owner.

## 3. Passive capture

`hooks/hooks.json` adds a `UserPromptSubmit` command hook running
`scripts/capture.sh`, which is inert without `MIND_REPO`, reads the hook JSON
on stdin, and appends one JSON line to `<pending file>`:

```json
{"ts": "2026-09-12T10:22:31Z", "session": "<session id>", "project": "<slug candidate>", "cwd": "<cwd>", "prompt": "<text>"}
```

- Pending file: `${MIND_HOME}/../pending.jsonl` (beside the checkout, never
  inside the data repo). `MIND_PENDING` overrides the path.
- Prompts shorter than 12 characters, or starting with `/` (a slash command),
  are not recorded.
- The file is capped at 2 MB: when larger, the oldest half is dropped before
  appending. Always exits 0; any failure is silent (stderr only).
- Never a `prompt`-type hook: a command hook that exits 0 cannot block a
  message (a documented mistake in a prior plugin).

Script support:

```
mind.py pending [--since <ts>] [--limit N]   # prints unprocessed lines as JSON, oldest first
mind.py pending --mark <ts>                  # records the processed watermark in <pending file>.processed
```

The watermark file holds one ISO timestamp; `pending` without `--since`
prints everything after the watermark.

## 4. Digest skill (`/mind:digest`)

Agent-driven, using the script for I/O:

1. `mind.py pending` (default: since the watermark; cap 200 lines).
2. Classify each prompt as **correction** (the owner rejected or redirected
   what the agent did), **directive** (a standing rule stated in the prompt),
   **answer** (the owner answered a question the agent asked), or **noise**.
   Corrections outrank directives outrank answers. Ignore anything about the
   task at hand with no reusable preference.
3. For each kept item, draft a note (schema rules; no secrets; no employer
   or third-party names; scope by the "true in another repo" test), run
   `ask` for a duplicate, and collect the drafts.
4. `mind.py propose <drafts> --topic digest-<date>`; then `mind.py pending --mark <last ts>`.
5. Report the PR URL and the classification counts. With nothing to propose,
   still mark the watermark and say so.

Runs on demand, or from a scheduled routine on the primary machine; the
watermark makes reruns idempotent.

## 5. Review skill (`/mind:review`) and stale notes

```
mind.py stale [--days 90] [--all]      # accepted notes whose `affirmed` is older than N days, oldest first
mind.py affirm <ID|slug/ID> [--strength must|should|default|optional]
mind.py retire <ID|slug/ID>
```

- `stale` prints `ID | title | scope | strength | affirmed | age` rows, all
  scopes with `--all`, global plus the current project by default.
  `strength: must` notes are listed but tagged `(must, no decay)`.
- `affirm` sets `affirmed: today`, optionally changes `strength`; commits
  `mind: affirm <ID>` and syncs to `main` (an owner action, not a proposal).
- `retire` sets `status: deprecated`, commits `mind: retire <ID>`, syncs.
- Revise = a new note through `propose` whose `supersedes` names the old ID;
  merging the PR is what supersedes. `propose` sets the old note's status to
  `superseded` in the same branch when a draft names it.

The review skill walks `stale` one note at a time with four verbs:
reinforce (`affirm`), weaken (`affirm --strength <lower>`), revise
(`propose` with `supersedes`), retire (`retire`). It does not lead the
witness: it shows the note, asks which verb, and never suggests retiring a
`must` note on age alone.

## 6. Lint

`mind.py lint [--days 180]` prints a report and always exits 0:

| check | row format |
|---|---|
| malformed note (fails `validate_meta` or ID shape) | `malformed: <path>: <errors>` |
| ID does not match filename prefix | `mismatch: <path> id=<ID>` |
| `supersedes` names a missing ID | `dangling: <ID> supersedes <missing>` |
| a note is named by another's `supersedes` but is still `accepted` | `unsuperseded: <old ID> (by <new ID>)` |
| two accepted notes with the same normalised title in one scope | `duplicate: <ID> and <ID>` |
| `project.md` still carries the stub body | `stub: <slug>` |
| accepted note older than `--days` | `stale: <ID> (<age> days)` |
| injected payload would exceed the budget | `budget: <N> of <M> global rows inject` |
| precedence note that names a missing ID | `dangling: <ID> refers to <missing>` |

Ends with `mind: lint clean` or `mind: lint found <N> issues`.

## 7. Precedence notes and toggles

- New type `precedence`, code `PREC`, in `TYPES` and `TYPE_CODES`. Body
  convention: "When <ID-A> conflicts with <ID-B>, <ID-A> wins when <condition>."
  Frontmatter adds an optional `refers: [ID-A, ID-B]` list field (a
  `LIST_FIELDS` entry, allowed by `validate_meta`), which `lint` checks.
- `ask` prints matching precedence notes first, tagged `[precedence]`, when a
  query hits two or more notes of the same stage. The protocol text tells the
  agent to check them before surfacing a conflict.
- Per-machine settings file `${MIND_HOME}/../settings.json` (override
  `MIND_SETTINGS`): `{"auto_answer": true, "escalate": false}`. Defaults
  apply when the file is missing. `inject` appends one line to the protocol:
  `Mode: apply notes silently and cite` or `Mode: confirm before applying a note`,
  and `Conflicts: use precedence notes` or `Conflicts: always ask`.
- `mind.py settings [--set key=value]` reads or writes the file.

## 8. Inject additions

After the existing sections, `inject` prints, when non-zero:

- `<N> open proposals: <url or branch> ...` (from `proposals`, only on
  `startup`/`resume`, cached to `<pending file>.proposals` for `clear`/`compact`),
- `<N> pending prompts since <watermark date>: run /mind:digest` when the
  pending file has 20 or more unprocessed lines,
- the malformed count line already present.

The `draft` count line stays for repos that still carry drafts.

## 9. Doctor

`mind.py doctor` prints one line per check and exits 0:

```
config: MIND_REPO=<redacted url> MIND_HOME=<path> MIND_TOKEN=<set|unset> MIND_PROJECT=<value|unset>
checkout: ok | missing | broken (<reason>)
upstream: main tracks origin/main | none
remote: reachable (<ms>) | unreachable (<last stderr line, redacted>)
identity: <user.email or "none, will use mind@localhost">
gh: <version> authenticated | present, not authenticated | missing
pending: <N> lines, <M> unprocessed, watermark <ts|none>
settings: auto_answer=<bool> escalate=<bool>
notes: <accepted> accepted, <draft> drafts, <malformed> malformed, <projects> projects
```

Every URL and stderr line goes through `_redact`.

## 10. Small changes

- `ask --limit N` (default 10) and `ask --stage <stage>`.
- `USAGE` lists every subcommand.
- The remember skill drops the `status: draft` option and points proposals at
  `/mind:digest` or `propose`.
- Protocol text adds: "Anything you inferred rather than the owner stated
  goes through `propose`, never `add`."

## 11. Security and failure rules

Unchanged from 0.1.0 and applied to every new path: `gh` is invoked with
`--` before positional values and never through a shell; branch and topic
names are validated with the slug rule; the pending file never enters the
data repo; capture and inject exit 0 always; every printed URL and stderr
line is redacted; `propose` never switches the shared checkout (it works in a
temporary worktree removed in a `finally`), and a failed push leaves the branch local with the
message `mind: proposal branch <name> is committed locally; push failed`.

## 12. Testing

`plugins/mind/tests/test_mind.py` grows with, at minimum:

- propose: branch name, one commit per note, PR body text (with `gh`
  monkeypatched to a fake that records its argv and returns a URL), no `gh`
  fallback message, checkout back on `main`, invalid draft rejects the batch,
  reuse of an existing branch, `supersedes` flips the old note in-branch.
- capture: the hook script writes one JSON line for a normal prompt, skips
  a slash command and a short prompt, exits 0 without `MIND_REPO`, caps the
  file.
- pending: since-watermark filter, `--mark` writes the watermark.
- stale/affirm/retire: exact rows, `must` tag, strength change, commits.
- lint: one test per check row with the exact line, plus `lint clean`.
- precedence: `ask` ordering and tag; `refers` parsed as a list.
- settings: defaults, `--set`, inject mode lines.
- doctor: every line present with a fake remote; redaction of a token URL.
- inject: proposals line and pending line thresholds.

Every assertion checks exact strings.
